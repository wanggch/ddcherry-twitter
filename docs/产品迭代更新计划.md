# X Post Saver 产品迭代更新计划

> **文档状态**：现行产品规划  
> **制定日期**：2026-08-12  
> **规划周期**：8 周，按实际投入滚动调整  
> **产品核心**：将喜欢的 X 帖子或文章快速归档为本地创作素材  
> **当前范围**：先完善插件的采集、整理和本地归档体验；插件满意后再联动本地服务

---

## 一、产品定义

### 1.1 一句话定位

X Post Saver 是一个面向个人创作者的素材采集插件：看到喜欢的 X 帖子或长文章时，快速提取内容、补充个人标记，并在本地保存成结构化素材，方便后续检索、整理和二次创作。

### 1.2 核心场景

```text
浏览 X 时发现有价值的内容
            ↓
点击插件，准确提取当前帖子或文章
            ↓
快速保存，或补充标签、备注和创作方向
            ↓
归档为本地素材卡 / 素材包
            ↓
在写作、选题、研究时检索并二次创作
```

### 1.3 核心价值

1. **采得准**：保存内容严格对应当前页面，保留来源和上下文。
2. **存得快**：高频采集尽量一次点击完成，不打断浏览。
3. **素材完整**：正文、作者、时间、图片、原始链接和采集信息统一保存。
4. **方便再用**：素材具有标签、备注、创作灵感等可检索信息，不是无结构的网页副本。
5. **本地可控**：素材文件保存在用户本地，不依赖云端账号才能访问。

### 1.4 产品不是什么

- 不是单纯的 Markdown 复制工具；
- 不是 X 内容阅读器或稍后读工具；
- 不是本轮就要完成的全功能素材管理系统；
- 不是在插件内直接完成 AI 改写和成稿；
- 不是依赖本地服务才能使用的前端壳。

Markdown 是当前最重要的素材载体，但“形成可复用的本地创作素材”才是最终目标。

## 二、用户与任务

### 2.1 目标用户

| 用户 | 收集内容 | 后续用途 |
|------|----------|----------|
| 自媒体创作者 | 观点、案例、金句、热点 | 选题、脚本、文章和社交内容 |
| 技术写作者 | 技术讨论、教程、工具信息 | 技术文章、实践验证和知识整理 |
| 研究型用户 | 长文章、数据、行业观点 | 研究笔记、趋势分析和资料引用 |
| 个人知识管理用户 | 有启发的帖子和文章 | 建立长期个人素材库 |

### 2.2 核心用户任务

| 阶段 | 用户任务 | 产品要求 |
|------|----------|----------|
| 发现 | 判断内容是否值得收藏 | 插件入口醒目但不干扰浏览 |
| 采集 | 保存正在看的准确内容 | 不错帖、不误判、不保存残缺内容 |
| 标记 | 记录“为什么收藏” | 可选标签、备注、素材类型和创作方向 |
| 归档 | 得到本地可长期保存的文件 | 文件名稳定、格式开放、来源可追溯 |
| 再利用 | 搜索、引用和改写素材 | 元数据结构统一，正文和个人想法分离 |

### 2.3 两种采集模式

#### 快速归档

适合浏览过程中连续收集：

- 点击工具栏图标；
- 自动提取内容；
- 按默认设置直接保存到本地素材收件箱；
- 显示“已归档”及文件名；
- 全程只需一次操作。

#### 整理后归档

适合重点素材：

- 打开素材预览；
- 查看正文、来源和图片；
- 添加标签、备注、素材类型、创作方向；
- 确认后保存到本地；
- 个人补充内容与原文分区保存。

两种模式输出同一素材结构，区别仅在于是否在归档前补充信息。

## 三、本地素材产物

### 3.1 素材卡

每次采集至少生成一个 UTF-8 Markdown 素材卡。建议结构：

```markdown
---
type: x-post
source: x
source_id: "1234567890"
source_url: "https://x.com/user/status/1234567890"
author_name: "作者名称"
author_handle: "@user"
published_at: "2026-08-10T10:00:00Z"
collected_at: "2026-08-12T09:30:00Z"
material_type: "观点"
tags:
  - 产品设计
  - 创作素材
---

# 素材标题

## 原始内容

帖子或文章正文。

## 媒体

![图片 1](原始图片地址)

## 我的备注

为什么收藏、自己的判断或可用角度。

## 创作方向

可延伸的选题、文章结构或表达方式。

## 来源

- 原文：[查看 X 原文](原始链接)
- 作者：作者名称（@user）
```

### 3.2 素材字段

| 分类 | 字段 | 是否必需 | 用途 |
|------|------|----------|------|
| 身份 | 内容类型、来源平台、来源 ID | 必需 | 去重和稳定识别 |
| 来源 | 原文链接、作者、主页 | 必需 | 回溯、引用和事实核验 |
| 时间 | 发布时间、采集时间 | 采集时间必需 | 时间排序与热点回顾 |
| 内容 | 标题、正文、图片 | 正文必需 | 素材主体 |
| 整理 | 素材类型、标签 | 可选 | 分类与检索 |
| 思考 | 个人备注、创作方向 | 可选 | 连接采集与二次创作 |
| 质量 | 提取版本、缺失字段 | 自动 | 后续迁移和问题诊断 |

发布时间缺失时保持为空，不能用采集时间冒充。

### 3.3 素材包

对于需要离线长期保留的重点内容，可导出素材包：

```text
2026-08-12-作者-素材标题-1234567890/
├── 素材.md
├── metadata.json
└── images/
    ├── 01.jpg
    └── 02.jpg
```

素材包分阶段实现：

- 第一阶段：Markdown 引用原始图片 URL；
- 第二阶段：通过浏览器下载能力保存 Markdown 与图片；
- 后续服务阶段：自动写入用户指定素材库、去重并维护目录。

### 3.4 插件阶段的本地保存边界

不接本地服务时，浏览器扩展无法在没有授权的情况下任意写入用户磁盘目录。因此当前采用以下可实现方案：

1. 默认使用浏览器下载能力保存到 `Downloads/X-素材收件箱/`；
2. 允许用户设置素材文件名、子目录和是否每次询问保存位置；
3. 支持下载单个 Markdown 素材卡；
4. 素材包可使用 ZIP 或多文件下载，但需评估浏览器下载体验；
5. 后续接入本地服务后，再实现指定素材库目录、媒体落盘、去重和自动整理。

| 长文章提取 | 已实现，但识别条件可能过宽 |
| Markdown 格式化 | 已实现基础格式，不是素材卡结构 |
| 一键复制 | 已实现，是当前默认路径 |
| Popup 预览 | 代码存在，但当前无正常入口 |
| 本地文件归档 | 尚未形成完整产品能力 |
| 标签、备注、创作方向 | 未实现 |
| 图片本地化 | 未实现 |
| 素材去重与历史 | 未实现 |

### 4.2 P0 问题

| 编号 | 问题 | 影响 |
|------|------|------|
| P0-01 | 当前 URL ID 可能与页面第一条帖子正文错配 | 归档错误素材，破坏素材库可信度 |
| P0-02 | 长文章探测条件过宽 | 普通帖子可能被错误归档为文章 |
| P0-03 | 核心字段缺失时仍可能输出 | 素材残缺且后续无法追溯 |
| P0-04 | 取不到发布时间时使用当前时间 | 素材时间信息失真 |
| P0-05 | 当前主路径偏向复制，未完成本地归档闭环 | 用户仍需手动建文件，核心价值未落地 |

### 4.3 P1 问题

- Popup、工具栏和右键菜单行为不一致；
- 缺少素材类型、标签、个人备注和创作方向；
- Markdown 中原文和个人补充内容没有明确分区；
- 文件名、目录、重复下载和图片保存规则不明确；
- Toast 注入可能失败，归档结果不够可靠；
- 页面未加载、字段缺失、下载失败等状态缺少针对性提示；
- 服务配置占据界面，但插件自身的素材归档设置不足。

## 五、产品决策

1. **本地归档是主操作**：默认按钮和成功反馈使用“归档素材”，不是“保存到后端”。
2. **复制是辅助能力**：保留复制 Markdown，方便临时粘贴，但不作为产品终点。
3. **素材卡是统一产物**：帖子、文章、快捷模式和预览模式共用一套素材结构。
4. **原文与个人内容分离**：不修改原始正文，备注和创作方向单独保存。
5. **快速归档默认零表单**：标签和备注可选，不强迫用户每次填写。
6. **重点素材允许整理**：预览模式可补充素材类型、标签、备注和创作方向。
7. **插件先使用下载目录**：在不依赖服务的前提下完成真实本地落盘。
8. **服务联动后置但方向明确**：未来服务用于指定目录、图片落盘、去重、检索和二创加工，不改变本地素材核心。
9. **正确性高于覆盖率**：无法确认内容时不归档猜测结果。

## 六、成功指标

### 6.1 北极星指标

**有效素材归档率**：用户发起归档后，在本地得到与当前页面匹配、核心字段完整且可再次使用的素材文件次数 / 总归档次数。

### 6.2 质量指标

| 指标 | 8 周目标 | 测量方式 |
|------|----------|----------|
| 内容识别准确率 | 核心样本集 100% | DOM fixture + 真实页面回归 |
| 核心字段完整性 | 缺失时 100% 拦截 | 自动化测试 |
| 素材卡格式稳定性 | 核心样本快照 100% 通过 | Markdown/Front Matter 快照 |
| 有效素材归档率 | >= 98% | 自动化测试 + 人工回归 |
| 来源可追溯率 | 100% 含来源 ID 和 URL | 结构断言 |
| 失败可解释率 | 100% 有原因和处理建议 | 错误场景测试 |
| 自动化场景覆盖 | >= 15 个核心场景 | CI 测试报告 |

### 6.3 体验指标

- 快速归档只需点击一次；
- 整理后归档最多三步：打开预览、补充信息、确认归档；
- 成功后明确显示文件名和归档位置；
- 用户不阅读文档也能理解“归档素材”“复制 Markdown”的差异；
- 标签、备注全部可跳过，不阻碍快速采集；
- 关闭所有本地服务后，插件仍能真实生成本地素材文件。

## 九、插件阶段候选能力

| 候选方向 | 对二次创作的价值 | 优先级 |
|----------|------------------|--------|
| 素材模板自定义 | 适配不同创作工作流 | 高 |
| 常用标签与最近标签 | 降低连续采集成本 | 高 |
| 一键记录收藏原因 | 提高素材未来可理解性 | 高 |
| 线程合并归档 | 保留完整观点上下文 | 中 |
| 引用帖展开 | 保存论点与引用关系 | 中 |
| 素材批量导出 | 迁移或集中整理素材 | 中 |
| 最近归档记录 | 找回、检查和再次编辑 | 中 |
| 本地全文搜索页面 | 在服务接入前提供轻量检索 | 低 |
| Firefox 支持 | 扩大使用范围 | 低 |

暂不投入：

- 插件内 AI 摘要、洗稿或自动成文；
- X 书签/点赞批量抓取；
- 云端账号和同步；
- 插件体验验收前的本地服务接口改造；
- 上传用户素材正文作为产品分析数据。

## 十、服务联动的后续定位

暂缓服务联动不代表改变产品方向。后续本地服务仍是“本地素材库”能力升级的重要组成部分，但必须建立在稳定插件体验之上。

### 10.1 服务阶段解决什么

| 插件阶段 | 服务联动后 |
|----------|------------|
| 下载到浏览器素材收件箱 | 自动写入用户指定素材库目录 |
| 图片使用远程链接或手动素材包 | 自动下载、去重和重写本地图片链接 |
| 单次文件级归档 | 建立素材索引、去重和更新机制 |
| 通过文件系统或编辑器查找 | 提供统一搜索、筛选和状态管理 |
| 手工整理标签和目录 | 按规则自动分类并保留人工修正 |
| 记录创作方向 | 支持基于本地素材的后续加工流程 |

### 10.2 启动门槛

只有同时满足以下条件，才启动服务联动版本：

- [ ] 帖子和文章核心样本识别准确率达到 100%；
- [ ] 素材卡结构连续两个版本无破坏性变化；
- [ ] 快速归档和整理归档都通过体验验收；
- [ ] 插件本身能稳定生成本地素材文件；
- [ ] 图片、标签、备注和创作方向字段已确定；
- [ ] Chrome 和 Edge 可独立安装和发布；
- [ ] 已明确首个联动版本只解决哪些本地素材管理问题。

### 10.3 联动时必须重新评审

1. 素材库目标目录与目录结构；
2. 图片下载、命名和去重策略；
3. 素材 ID、幂等和更新规则；
4. 插件离线、服务未启动和版本不兼容时的降级；
5. 标签、备注和创作状态的双向修改边界；
6. 本地搜索、AI 加工和二次创作能力由哪一端承担。

## 十一、优先级规则

每个版本按以下顺序裁剪：

1. **素材正确性**：是否可能保存错误、残缺或失真的素材；
2. **本地归档闭环**：素材是否真实落盘并可再次打开；
3. **来源可追溯性**：能否返回原文核验和引用；
4. **二次创作价值**：是否帮助记录、查找和重新利用素材；
5. **采集效率**：是否减少高频收藏操作；
6. **交互和视觉体验**；
7. **外部服务联动**：插件验收后才进入规划。

出现以下情况时，新增功能自动让位于修复：

- 保存错帖、错文章或错作者；
- 来源 ID、原文链接或正文丢失；
- 原文和用户备注混合，无法区分；
- 下载文件损坏或无法再次打开；
- X 页面变化导致核心样本识别失败。

## 十三、评审节点

### v1.0.1 素材标准评审

- 哪些字段是素材卡必需字段；
- 帖子标题如何生成；
- 素材类型默认值和候选项；
- Markdown、Front Matter 和图片的默认格式；
- 原文、个人备注和创作方向的分区结构。

### v1.2.0 交互评审

- 默认采用快速归档还是先预览；
- Popup 的字段密度和主次操作；
- 标签与备注是否足够轻量；
- 归档成功后是否需要打开文件或目录；
- 服务配置采用隐藏还是实验入口。

### v1.3.0 独立产品评审

- 插件是否真正完成“发现 -> 采集 -> 本地归档”的闭环；
- 素材文件是否方便未来查找和二次创作；
- 图片和重复素材策略是否可接受；
- 功能、交互和视觉是否达到独立发布标准。

### v2.0 服务联动评审

插件体验满意后，围绕“如何让本地素材归档更自动、更完整、更易检索和二次创作”单独制定联动计划，不直接把当前历史接口视为最终方案。
