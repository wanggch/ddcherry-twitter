你现在是资深前端工程师，熟悉 Chrome 扩展（Manifest V3）、TypeScript/JavaScript、X（原 Twitter）页面结构，以及与后端服务的集成。

目标：帮我从零开发一个 Chrome 浏览器插件，用于在浏览 X（原 Twitter）帖子时，快速调用后台接口保存帖子内容。要求插件完整可用、可打包发布，并附详细说明。

【功能需求】

1. 基础功能
   - 用户在 X 的帖子详情页时，通过以下方式之一触发保存：
     - 点击扩展图标的 popup 里的「保存到后台」按钮
     - 或者在帖子区域上右键菜单「保存这个帖子」
   - 插件从当前页面中自动提取以下信息：
     - 帖子 ID
     - 帖子 URL
     - 帖子文本内容（支持多行）
     - 帖子内所有图片的 URL
     - 作者信息：
       - 显示名（display name）
       - 用户名（@handle）
       - 头像地址
       - 个人主页链接
     - 帖子发布时间（如果方便获取）
   - 将以上数据通过 HTTP POST 调用我提供的后台接口进行保存。

2. 后台接口（假设接口如下，可根据需要抽象封装）
   - 接口 URL：由用户在插件设置页配置（例如 https://api.example.com/x/savePost）
   - 请求方式：POST JSON
   - 示例请求体：
     {
       "postId": "1234567890",
       "url": "https://x.com/xxx/status/1234567890",
       "content": "这里是帖子文本",
       "images": ["https://...img1", "https://...img2"],
       "author": {
         "displayName": "作者昵称",
         "handle": "@someone",
         "avatarUrl": "https://...avatar",
         "profileUrl": "https://x.com/someone"
       },
       "createdAt": "2025-01-01T12:34:56Z"
     }
   - 支持在请求头里附带一个可选的 API Key，例如：
     - Header: Authorization: Bearer <API_KEY>

3. 配置与存储
   - 在插件的 Options 页面或 Popup 里提供配置项：
     - 后台接口地址（必填）
     - API Key（可选）
   - 使用 chrome.storage.sync 存储配置，以便多设备同步。
   - 在 UI 中给出简单的校验与错误提示（如未配置 URL 时禁止调用）。

4. UI 与交互
   - Popup 中显示：
     - 当前页是否是 X 帖子详情页的识别状态
     - 当前识别到的作者、部分内容预览（比如前 50 个字）
     - 一个「保存到后台」按钮
     - 调用后展示保存成功/失败提示信息
   - 右键菜单（contextMenus）中：
     - 在 X 页面选中文字或空间区域时，提供「保存当前帖子」菜单项。
   - 错误处理：
     - 网络错误、接口返回错误、解析不到帖子信息时给出清晰提示。

【技术要求】

1. 使用 Manifest V3：
   - 编写 manifest.json，使用 "service_worker" 作为 background。
   - 权限最小化：
     - 至少包括：tabs、storage、contextMenus、activeTab、scripting，必要时再补充。
   - 匹配规则仅针对 X 相关域名：
     - https://x.com/*
     - https://twitter.com/*（兼容老链接）

2. 代码结构建议（供你参考调整）
   - manifest.json
   - src/
     - content-script/
       - contentScript.js / .ts   （负责解析页面、抽取帖子数据）
     - background/
       - serviceWorker.js / .ts   （负责接收消息、调用后台接口）
     - popup/
       - popup.html
       - popup.js / .ts
     - options/
       - options.html
       - options.js / .ts
     - common/
       - types.ts（定义帖子/作者等类型）
       - apiClient.ts（封装调用后台接口逻辑）
       - storage.ts（封装读写 chrome.storage）
   - 如果你认为用 TypeScript + 简单打包工具（如 Vite）更好，也可以给出完整配置。

3. 解析 X 页面时的注意点
   - X 前端结构经常变动，你需要：
     - 尽量使用稳定的 DOM 选择器或 data- 属性
     - 或辅助使用 meta 标签（og:title / og:image 等）作为兜底方案
   - 尽可能把抽取逻辑封装成独立函数，易于日后维护（DOM 变了可以集中修改）。
